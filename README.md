# こころの庭

過食しなかった日を記録して、花や動物を育てるiPhone向けアプリです。
AIやAPIは使わず、記録はiPhoneの中だけに保存されます。外部には送信しません。

---

## 1. ファイル構成

```
kokoro-niwa/
├── index.html          画面の骨組み
├── style.css           見た目（色・大きさ・配置）
├── app.js              動き（記録・計算・育成・バックアップ・SOS）
├── manifest.json       ホーム画面に追加したときの名前やアイコン
├── service-worker.js   電波がなくても開けるようにする仕組み
├── icons/
│   ├── icon-180.png    iPhoneのホーム画面用アイコン
│   ├── icon-192.png
│   └── icon-512.png
└── README.md           この説明書
```

ファイルはすべて完成済みです。中身を書き換える必要はありません。
フォルダの形（`icons` フォルダの中にアイコンが入っている形）は、このまま保ってください。

---

## 2. 無料で公開する（GitHub Pages）

パソコンで作業するのがいちばん簡単です。所要時間は15分ほどです。

1. **GitHubのアカウントを作る**
   https://github.com を開き、「Sign up」から無料アカウントを作ります。
   ユーザー名は公開URLに入ります（例：`hanako` → `https://hanako.github.io/...`）。

2. **置き場所（リポジトリ）を作る**
   ログイン後、右上の「＋」→「New repository」。
   - Repository name：`kokoro-niwa`
   - 「Public」を選ぶ（無料で公開するために必要です）
   - 「Create repository」を押す

   Publicにしても、公開されるのはアプリのプログラムだけです。**あなたの記録は公開されません**（記録はiPhoneの中にだけあります）。

3. **ファイルをアップロードする**
   作ったリポジトリの画面で「uploading an existing file」を押します。
   `kokoro-niwa` フォルダの**中身**（`index.html` や `icons` フォルダなど）をまとめてドラッグして入れ、下の「Commit changes」を押します。
   アップロード後、一覧に `index.html` と `icons` フォルダが並んでいればOKです。

4. **公開をオンにする**
   リポジトリの「Settings」→ 左の「Pages」。
   「Branch」で `main`、フォルダは `/ (root)` を選んで「Save」。

5. **1〜3分待つ**
   同じ画面の上に `https://ユーザー名.github.io/kokoro-niwa/` と表示されたら公開完了です。
   このURLをメモしておいてください。

> **大事：このURLは今後ずっと変えないでください。**
> 記録はURLごとに保存されるので、リポジトリ名やユーザー名を変えると、それまでの記録が見えなくなります。

## 3. iPhoneのホーム画面に追加する

1. iPhoneの**Safari**で、公開したURLを開きます（ChromeなどではなくSafari）。
2. 画面下の共有ボタン（四角から上向きの矢印）を押します。
3. 「ホーム画面に追加」を選び、右上の「追加」を押します。
4. ホーム画面に「こころの庭」のアイコンができます。**これからは必ずこのアイコンから開いてください。**

> **なぜアイコンから開くのか**
> iPhoneでは、Safariで開いたときと、ホーム画面のアイコンから開いたときで、記録の保存場所が別々になります。
> Safariでつけた記録はアイコン側には出てきません。記録は最初からアイコン側でつけてください。
> また、ホーム画面に追加したアプリは、Safariよりも記録が消されにくくなります。

---

## 4. オフライン（電波がないとき）について

- 一度ホーム画面のアイコンから開けば、その後は電波がなくても開けます。
- 記録・カレンダー・育成・SOSは、すべて電波なしで使えます。
- アプリの更新（あとで中身を直したとき）は、電波があるときに開くと反映されます。反映には、アプリを2回開き直す必要があることがあります。

## 5. データを守るために（バックアップと復元）

### 記録が消える可能性があるとき
- ホーム画面のアイコンを削除したとき
- 設定アプリ →「Safari」→「履歴とWebサイトデータを消去」をしたとき
- iPhoneを買い替えたとき・初期化したとき
- 公開URLが変わったとき

### バックアップの保存（iCloud Driveへ）
1. アプリの「設定」→「バックアップを保存」
2. 出てきたメニューで「"ファイル"に保存」を選ぶ
3. 「iCloud Drive」を選んで「保存」

最後の保存から7日たつと、ホーム画面に「バックアップを保存しませんか？」と表示されます。表示されたら保存しておくと安心です。

「文字でコピー」を押すと、記録を文字としてコピーできます。メモアプリに貼り付けて保存する方法もあります。

### 復元（戻し方）
1. アプリの「設定」→「バックアップから戻す（ファイルを選ぶ）」
2. iCloud Driveに保存した `kokoro-niwa-backup-日付.json` を選ぶ
3. 「このバックアップで上書きしますか？」と記録の日数が表示されるので、確認して「上書きして戻す」

文字でコピーしたものは、「コピーした文字を貼り付け」欄に貼り付けて「貼り付けた内容を読み込む」を押します。

### iPhoneを買い替えるとき
1. 古いiPhoneでバックアップをiCloud Driveに保存
2. 新しいiPhoneのSafariで公開URLを開き、ホーム画面に追加
3. アイコンから開いて、設定 → バックアップから戻す

### 試作版の記録を引き継ぐとき
試作版の「設定」→「文字でコピー」でコピーし、公開版の「設定」→「コピーした文字を貼り付け」に貼り付けて読み込んでください。

---

## 6. アプリを直したいとき

1. GitHubのリポジトリで、直したファイルを同じ名前で上書きアップロードします。
2. `service-worker.js` の `kokoro-niwa-app-v1` の数字を1つ上げます（v1 → v2）。これをしないと、iPhoneに古い版が残ったままになります。
3. iPhoneでアプリを2回ほど開き直すと新しい版になります。

`app.js` の先頭近くにある `KEY = 'kokoro-niwa-v1'` は**変えないでください**。変えると今までの記録が読めなくなります。

花が咲くまでの日数や応援メッセージは、`app.js` の上のほう（「設定値」の部分）で変えられます。

## 7. 動作確認のチェックリスト

公開後、iPhoneで次を確かめてください。

**記録**
- [ ] ホームで「過食なし」を押すと、今月と合計の日数が1増える
- [ ] 「過食あり」に押し直すと、日数が1減り、責める表示が出ない
- [ ] 「体を動かした」にチェックすると、カレンダーのその日に小さな点がつく
- [ ] アプリを完全に閉じて開き直しても、記録が残っている

**カレンダー**
- [ ] 前の月・次の月に移動できる（今月より先には進まない）
- [ ] 過去の日付を押して、記録をつけたり「未記録に戻す」ができる
- [ ] 未来の日付は押せない
- [ ] 記録していない日が「過食あり」扱いになっていない

**育てる**
- [ ] 過食なしの日が増えると、花の段階が進む（2日で芽、21日で開花）
- [ ] 過食ありの日を記録しても、花や動物が減ったり消えたりしない
- [ ] 動物の名前を変えられ、開き直しても残っている
- [ ] 合計3日などでバッジがもらえ、花びらのお祝いが出る

**SOS**
- [ ] SOSボタンで15分タイマーが動き、呼吸の案内が変わる
- [ ] 「少し落ち着いた」を押すと、育てる画面に回数が出る
- [ ] 設定で「代わりにやってみること」を追加・削除できる

**データ**
- [ ] 「バックアップを保存」でiCloud Driveに保存できる
- [ ] 保存したファイルから復元でき、上書き前に確認が出る
- [ ] 「すべて削除する」は2回押さないと消えない
- [ ] 機内モードにしても、アイコンから開ける

**日付**
- [ ] 夜0時をまたいでアプリに戻ったとき、日付が今日に変わっている

## 8. 困ったときは

- **アイコンから開いたら記録が空っぽ**：Safariでつけた記録はアイコン側に出ません。Safariで「設定」→「文字でコピー」し、アイコン側で貼り付けて戻してください。
- **「記録を保存できない状態です」と出る**：プライベートブラウズになっていないか確認してください。設定アプリ →「Safari」→「詳細」→「Webサイトデータ」が消えていないかも確認してください。
- **公開URLを開くと「404」**：Pages の設定から数分待ってください。`index.html` がリポジトリの一番上（フォルダの中ではなく）にあるかも確認してください。
